\section*{S1. Pre-registration, amendments and the post-hoc ablation}
\addcontentsline{toc}{section}{S1. Pre-registration, amendments and the post-hoc ablation}
The analysis plan (\texttt{ANALYSIS\_PLAN.md}) and SHA-256 hashes of all code were committed before each scoring of the official test folds.
\begin{itemize}
\item \textbf{Original freeze} (\texttt{results/freeze\_hashes\_original\_plan.txt}). Under it, the design was fixed on inner CV of fold~0's training rows. A run under this plan produced test predictions that were never scored; they are archived unscored.
\item \textbf{Amendment~1 = run~1} (\texttt{results/freeze\_hashes.txt}, plan Section~8). Written before any scoring. It moved the choice among the explored design configurations inside every official training fold (Section~S3).
\item \textbf{Amendment~2 = run~2} (\texttt{results/freeze\_hashes\_amendment2.txt}, plan Sections~9--11). Written after run~1 had been scored.
  \begin{itemize}
  \item It changed the expert pool, the features (including the disclosed DFT block) and the correction gate.
  \item It was frozen before any run-2 test prediction, and scored once.
  \item The design evidence (fold~0 training rows only) is in \texttt{results/design\_a2/DESIGN\_LOG\_A2.md}.
  \end{itemize}
\item \textbf{Post-hoc ablation} (plan Section~12). Written after run~2 had been scored and not used for any selection. It re-runs the frozen run-2 code without the DFT block (all tasks) or without the hurdle experts (expt\_gap).
\item \textbf{Deviations} are listed in plan Sections~7 and~11.
\end{itemize}
The leaders' per-sample predictions come from the public \texttt{matbench} repository (\texttt{benchmarks/matbench\_v0.1\_\{TPOT,darwin,modnet\_v0.1.12\}/results.json.gz}).

\section*{S6. Ideation and prior-art process}
\addcontentsline{toc}{section}{S6. Ideation and prior-art process}
Literature search, prior-art checking and idea generation for run~1 used the ResearchStudio Idea skills (paper-search, scoop-check, idea-spark), driven by an AI assistant. All records are in the repository (\texttt{research/}, \texttt{ideaspark\_run/}).

\begin{itemize}
\item \textbf{Prior-art verdict: medium overlap.} Every component has ancestors (stacking, regression kriging, $\Delta$-learning), but we found no work that combines them on these tasks.
\item \textbf{Idea card.} idea-spark proposed the fold-matched correction (Section~S2). Its coherence check verified the decomposition on synthetic instances.
\item \textbf{Run outcome.} The run ended in a \texttt{needs\_work} state because of an internal inconsistency in the tool's novelty gate. We therefore pre-registered the proposal only as a secondary arm.
\item \textbf{Run-2 literature check.} A further search on DFT-informed and multi-fidelity prediction of experimental band gaps (\texttt{research/paper\_search\_dft/}) added the band-gap transfer and multi-fidelity references cited in the main text.
\end{itemize}

\section*{S7. Leaderboard snapshot and label-based classification scores}
\addcontentsline{toc}{section}{S7. Leaderboard snapshot and label-based classification scores}
The leaderboard values (\texttt{results/leaderboard\_snapshot.json}) were taken from the per-task Matbench pages on 18 October 2026. The pages list merged entries only; the merge status was rechecked on 19 October 2026 (last merge January 2024).
For every listed classification entry the reported mean ``ROC-AUC'' equals the mean balanced accuracy to four decimals.
\begin{itemize}
\item Darwin's public results contain boolean labels.
\item MODNet v0.1.12's contain probabilities, yet its board ROC-AUC equals its balanced accuracy. This is consistent with the older \texttt{matbench} scoring thresholding probabilities at 0.5.
\end{itemize}
We prepared two unsubmitted result files for each run: one with labels at the inner-CV threshold (comparable with the board) and one with probabilities.

\section*{S8. Post-hoc ablation: per-fold values and execution}
\addcontentsline{toc}{section}{S8. Post-hoc ablation: per-fold values and execution}
The ablation (plan Section~12) was written after run~2 had been scored. It was not used for any selection, and it changes neither the reported pipeline nor the prepared leaderboard files.

\begin{itemize}
\item \textbf{Code.} Each variant re-runs the frozen run-2 code unchanged (\texttt{src/run\_ablation.py}), with either the \texttt{dft\_*} block or the three hurdle experts removed.
\item \textbf{Cached experts.} Expert caches were reused only where the inputs were byte-identical:
  \begin{itemize}
  \item in the no-DFT variant, the experts that read only Magpie or element-fraction columns;
  \item in the no-hurdle variant, all remaining experts.
  \end{itemize}
\item \textbf{Interrupted run.} The run was interrupted once, when all workers were killed.
  \begin{itemize}
  \item Before any scoring, the 16 completed folds were checked (loadable, finite, test identifiers equal to the official folds) and committed.
  \item The 9 interrupted folds (glass 0--3, steels 0--4) were then rerun with the same launcher. Their partially written expert caches were checked to load and reused by the resumable pipeline. All experts are deterministic (deterministic LightGBM, fixed seeds).
  \end{itemize}
\item \textbf{Scoring.} All predictions were committed before the single scoring run (\texttt{src/evaluate\_ablation.py}). It uses the same paired bootstrap as the run-2 evaluation, with no multiplicity adjustment because the ablation is descriptive.
\end{itemize}
