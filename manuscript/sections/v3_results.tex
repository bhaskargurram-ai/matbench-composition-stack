\subsection{The DFT-informed pipeline versus the leaderboard (run 2)}
Table~\ref{tab:a2leader} and Fig.~\ref{fig:a2} compare the frozen run-2 pipeline with each task's leader.

\paragraph{expt\_gap}
The MAE is \AtwoFinalGap{}~eV against \AtwoLeaderGap{}~eV for Darwin. The difference is $\Delta=\AtwoDeltaGap$~eV (95\% CI [\AtwoCIloGap, \AtwoCIhiGap]; \AtwoPHolmExprGap). This is the only task that meets our pre-registered rule for beating the leader.

\paragraph{expt\_is\_metal and steels}
The pipeline is statistically on par with the leaders:
\begin{itemize}
\item expt\_is\_metal: balanced accuracy \AtwoFinalMetal{} versus \AtwoLeaderMetal{} (\AtwoPHolmExprMetal);
\item steels: MAE \AtwoFinalSteels{} versus \AtwoLeaderSteels~MPa (\AtwoPHolmExprSteels).
\end{itemize}

\paragraph{glass}
The pipeline is clearly behind MODNet v0.1.12: \AtwoFinalGlass{} versus \AtwoLeaderGlass{} (\AtwoPHolmExprGlass). This also holds for the probability ROC-AUC (\AtwoAUCGlass{} versus \AtwoLeaderAUCGlass).

\paragraph{Caveat}
These are not like-for-like comparisons. Our pipeline uses an external DFT block for expt\_gap and expt\_is\_metal. The leader on those tasks, Darwin, uses no external property data but brings external knowledge from language-model pre-training (Section~\ref{sec:discussion}).

\subsection{How much of the gain is due to DFT features: post-hoc ablation}
\label{sec:ablation}
The ablation was written after run~2 had been scored and was not used for any selection. The reported pipeline and the prepared leaderboard files are unchanged.
It re-runs the frozen run-2 code with one component removed:
\begin{itemize}
\item without the DFT block, on all four tasks;
\item without the three hurdle experts, on expt\_gap only.
\end{itemize}
Each variant was scored once, using the run-2 paired bootstrap (Table~\ref{tab:ablation}). The $p$-values are descriptive and unadjusted.

\paragraph{expt\_gap}
\begin{itemize}
\item \textbf{Without the DFT block,} the MAE rises from \AtwoFinalGap{} to \AblNoDftGap{}~eV ($\Delta=\AblNoDftGapDelta$~eV, 95\% CI [\AblNoDftGapCIlo, \AblNoDftGapCIhi], \AblNoDftGapRel\%, \AblNoDftGapPExpr). It is worse in \AblNoDftGapFoldsWorse/5 folds. This removes \AblNoDftGapShareOfLeaderGain\% of the full pipeline's \AtwoDeltaGap~eV margin over Darwin.
\item \textbf{Without the hurdle experts,} the MAE rises to \AblNoHurdleGap{}~eV ($\Delta=\AblNoHurdleGapDelta$~eV [\AblNoHurdleGapCIlo, \AblNoHurdleGapCIhi], \AblNoHurdleGapRel\%, \AblNoHurdleGapPExpr; \AblNoHurdleGapFoldsWorse/5 folds). This removes \AblNoHurdleGapShareOfLeaderGain\% of the margin.
\item \textbf{The two components are not additive.} Each removal alone erases most of the margin. Each variant is statistically on par with Darwin:
  \begin{itemize}
  \item without DFT: $\Delta=\AblNoDftGapVsLeader$~eV, \AblNoDftGapVsLeaderPExpr;
  \item without hurdles: $\Delta=\AblNoHurdleGapVsLeader$~eV, \AblNoHurdleGapVsLeaderPExpr.
  \end{itemize}
  Under our claim rule, therefore, neither the DFT block nor the hurdle experts alone would have been enough to beat the leader. This is consistent with the two carrying overlapping information, because the DFT gap and metal flag also indicate which compounds have $E_g=0$.
\end{itemize}

\paragraph{expt\_is\_metal}
Without the DFT block the balanced accuracy falls from \AtwoFinalMetal{} to \AblNoDftMetal{} ($\Delta=\AblNoDftMetalDelta$ [\AblNoDftMetalCIlo, \AblNoDftMetalCIhi], \AblNoDftMetalPExpr; \AblNoDftMetalFoldsWorse/5 folds).
\begin{itemize}
\item The variant is significantly below Darwin ($\Delta=\AblNoDftMetalVsLeader$, \AblNoDftMetalVsLeaderPExpr), so parity with the leader on this task also depends on the DFT block.
\item The probability ROC-AUC falls less, from \AblNoDftMetalAtwoAUC{} to \AblNoDftMetalAUC.
\end{itemize}

\paragraph{steels and glass}
The DFT block matches no steels and 1\% of glass compositions, so it serves mainly as a negative control. Removing it changes nothing detectable:
\begin{itemize}
\item steels: \AblNoDftSteels{} versus \AtwoFinalSteels~MPa (\AblNoDftSteelsPExpr);
\item glass: \AblNoDftGlass{} versus \AtwoFinalGlass{} balanced accuracy (\AblNoDftGlassPExpr).
\end{itemize}
The small per-fold differences (SI Section~S8) most likely arise because removing these constant or nearly constant columns changes the random column subsampling of the tree ensembles.

\subsection{The local residual correction: a negative finding (run 1)}
Run~1 pre-registered a single primary question: does the novelty-damped local OOF residual correction improve a cross-fitted stack on these tasks?
\begin{itemize}
\item \textbf{expt\_gap.} It improved the MAE from \GapStack{} to \GapStackLocal{}~eV (\RelGap\%; 5/5 folds; $p_\mathrm{Holm}=\PHolmGap$).
\item \textbf{steels.} No detectable effect (\RelSteels\%).
\item \textbf{Classification tasks.} The inner selection almost never switched the correction on (\GlassNaiveOn/5 and \MetalNaiveOn/5 folds).
\end{itemize}
Stratifying the test errors by distance to the nearest training composition showed the correction \emph{hurting} for near-duplicate compositions (expt\_gap \GapLocalQOne\%, steels \SteelsLocalQOne\% in the nearest quartile).
A fold-matched variant designed to remove the double counting behind this did not help (\GapStackFmVsStackLocalRel\% MAE versus the naive correction on expt\_gap).
In run~2 the nested gate kept the correction in none of the 20 folds.
The SI reports all run-1 arms, ablations and controls.

\subsection{Stacking and the two runs}
Run~2 improved on run~1 on every task (Table~\ref{tab:a1a2}). The improvement is large on expt\_gap and expt\_is\_metal, and within noise on steels ($p=\AtwoVsAonePSteels$).
The simplex stack beat the best single expert selected by inner CV only on glass (\AtwoStackVsBestGlass\% ROC-AUC, $p=\AtwoStackVsBestPGlass$). Elsewhere it matched that expert.
On steels, extremely randomised trees on element fractions alone reached \AtwoBestSteels~MPa as the best single expert, against \AtwoStackSteels~MPa for the pre-registered stack, which we report.
One official fold took a median of \AtwoWallMinSteels--\AtwoWallMinGap{} minutes on a 24-core CPU workstation with five parallel workers.
